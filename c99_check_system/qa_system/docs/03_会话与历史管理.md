# 会话管理与历史存储

## 1. Session 生命周期

```text
POST /api/qa/session
  → { session_id: "<uuid>" }
        │
        ▼
WS /api/qa/ws?session_id=xxx   （推荐，流式）
  或
POST /api/qa/ask { session_id, question }
        │
        ▼
QA Agent：Retriever → Summarizer → 生成回答
        │
        ▼
写入 user + assistant（默认本地 SQLite：data/sessions.db）
```

默认 **不连远程 MySQL**（`SESSION_BACKEND=sqlite`）。  
无 `session_id` 的 `/ask` 为单轮。

---

## 2. 存储后端

| SESSION_BACKEND | 说明 |
|-----------------|------|
| `sqlite`（默认） | 本地文件 `SQLITE_SESSION_PATH`，支持多轮，无需服务器 |
| `mysql` | 远程/本地 MySQL（可选） |

C99 条款知识仍在 FAISS，与会话库无关。

---

## 3. session_id

- 由 `uuid.uuid4()` 生成
- 前端自行持久化（localStorage 等）

---

## 4. 历史与续写

| 场景 | 行为 |
|------|------|
| `/ask` 带 session_id | 读历史 → Agent → 写回本地库 |
| `/ask` 不带 session_id | 单轮 |
| WebSocket | 流式写库 + cursor 续写 |

多轮指代由 Retriever 查询改写 + QA prompt 结合历史理解。
