# 外部对接指南（前端 / 其他调用方）

供 **chat-web 前端** 或其他系统调用本 C99 测试代码生成后端时使用。
管理员反馈统计接口仅内部运维，可忽略。

---

## 1. 服务地址

| 场景 | Base URL |
|------|----------|
| 本机 | `http://localhost:8000` |
| 局域网 | `http://<后端机器局域网IP>:8000` |

| 用途 | 地址 |
|------|------|
| Swagger | `{BASE}/docs` |
| 健康检查 | `{BASE}/health` |
| HTTP API | `{BASE}/api/qa` |
| WebSocket | `ws://{host}:8000/api/qa/ws?session_id=...` |

Windows 查 IP：`ipconfig` → 取当前上网网卡的 IPv4（非 127.0.0.1）。

前端配置文件通常为：`chat-web/src/api/chat.ts`（`HTTP_BASE` / `WS_BASE`）。

---

## 2. 最小对接步骤

1. 确认 `GET /health` 返回 `status=ok` 且 `faiss_ready=true`
2. `POST /api/qa/session` 拿 `session_id`
3. 连接 WebSocket，发送 `{"type":"message","content":"条款编号或中文描述"}`
4. 处理 `agent_step` / `chunk` / `done`
5. 用 `done.sources` 渲染条款来源（见字段映射）

也可用 `POST /api/qa/ask` 做非流式联调。

---

## 3. 溯源展示映射

| 协议字段 | 展示文案 |
|----------|----------|
| `museum_name` | 标准名 |
| `object_id` | 条款编号 |
| `detail_url` | 原文链接 |
| `accession_number` | 可选：分段 ID |

---

## 4. 推荐联调问题

- `6.5.2.2`（函数调用的规则）
- `6.5.5`（乘法运算）
- `7.21.2.3`（strcpy 的规则）
- 中文描述：「函数调用时参数如何求值？」「malloc 失败时返回什么？」

---

## 5. 注意

- CORS 已放宽为 `*`，浏览器本机联调一般无阻
- 多轮历史：默认 SQLite，`ENABLE_MYSQL=on` 时走 MySQL
