# C99 测试代码生成子系统 — 整体介绍

## 1. 定位

本子系统是「面向编译器的测试用例理解与测试规约关联匹配研究」项目中的 **RAG + Agent 后端**。

输入 C99 条款编号（如 `6.5.2.2`）或中文描述（如「函数调用的规则」），系统经 **FAISS 向量检索**召回对应条款，由 **检索 / 总结 / 生成** 三 Agent 协作生成**可编译的 C 测试代码**（正向 + 负向），并通过 REST + WebSocket 对外提供接口。

| 模块 | 位置 | 状态 |
|------|------|------|
| 数据切分与向量化 | `data_c99/` | 已交付（581 条款） |
| RAG + Agent + API | 本仓库后端 | 已跑通 |
| 前端 UI | `chat-web/` | 已对接 |

---

## 2. 建设目标

| 目标 | 说明 |
|------|------|
| 可检索 | FAISS 语义检索 C99 条款（`chunks.jsonl`），支持编号精确匹配 + 中文跨语言 |
| 可生成 | 多轮会话、流式输出，生成带验证点注释的 C 测试代码 |
| 可解释 | `agent_step` 展示检索过程；`sources` 标注标准名与条款编号 |
| 可对接 | 稳定 REST + WebSocket，供前端独立开发 |

---

## 3. 系统组成

```text
C99_check_system/
├── qa_system/     # 后端 FastAPI :8000（本子系统）
└── chat-web/      # 前端 Vue3 :5173
```

**后端技术要点：**

- FastAPI + Swagger（`/docs`）
- 三 Agent：Retriever → Summarizer → QA（生成测试代码）
- 知识库：C99 条款 JSONL → 向量化 → FAISS
- LLM：DeepSeek 或任意 OpenAI 兼容 API

---

## 4. 一次生成流程

```text
条款编号 / 中文描述
  → Retriever Agent（编号精确匹配 / 关键词映射 / FAISS 语义检索）
  → Summarizer Agent（整理 RAG context + sources）
  → QA Agent（生成正向 + 负向 C 测试代码，流式输出）
  → REST 响应 或 WebSocket chunk/done
```

无检索命中时：明确告知未检索到对应条款，不调用模型凭空生成。

## 5. 功能清单

| 功能 | 说明 |
|------|------|
| 单轮生成 | `POST /api/qa/ask` |
| 流式多轮 | `WS /api/qa/ws` |

| 生成溯源 | `sources`：标准名 / 条款编号 / 链接 |
| 用户反馈 | `POST /api/qa/feedback` |
| 健康检查 | `GET /health`（含 `faiss_ready`） |

## 6. 部署要点

1. 配置 `qa_system/.env`（LLM 地址与密钥）
2. `pip install -r requirements.txt`
3. `python scripts/build_faiss_index.py`（读 `data_c99/`）
4. `uvicorn main:app --reload --port 8000`

详见根目录 README 与 [09_联调说明](./09_联调说明.md)。
