# C99 测试代码生成后端 — 功能测试用例

> 环境：`http://localhost:8000`，FAISS 已用 `data_c99` 构建，LLM 已配置。
> 记录列：实际结果 / 结论（通过 · 失败 · 部分通过）

---

| 编号 | 测试项 | 步骤 | 预期 |
|------|--------|------|------|

## 1. 检索正确性（RAG，P0）

| 编号 | 问题 / 查询 | 预期命中（Top-1） | 优先级 |
|------|-------------|-------------------|--------|
| TC-1.1 | 编号精确匹配 `6.5.2.2` | `6.5.2.2` Function calls | P0 |
| TC-1.2 | 中文描述「函数调用的规则」 | `6.5.2.2` | P0 |
| TC-1.3 | 中文描述「乘法运算」 | `6.5.5` | P0 |
| TC-1.4 | 库函数「malloc 失败时返回什么」 | `7.20.3.3` malloc | P0 |
| TC-1.5 | 完全无关的问题 | 无强相关条款 / `not_found` | P0 |

**通过标准：** 相关查询 `has_kg_facts=true` 且 `sources` 中标准名、条款编号合理；无关问题不凭空编条款。

---

## 2. 端到端生成（Agent + LLM，P0）

用 PowerShell：

```powershell
Invoke-RestMethod -Uri "http://localhost:8000/api/qa/ask" `
  -Method POST -ContentType "application/json" `
  -Body '{"question":"6.5.2.2 函数调用的规则"}'
```

| 编号 | 检查点 | 预期 |
|------|--------|------|
| TC-2.1 | `answer` 非空 | 返回 C 测试代码（含 `#include` / 函数体） |
| TC-2.2 | `has_kg_facts` | `true` |
| TC-2.3 | `sources` | 含 `ISO/IEC 9899:1999 (C99)` 与 `6.5.2.2` |
| TC-2.4 | 生成代码可编译运行 | 用 MSVC `cl` / gcc 编译，运行 exit=0 |

## 3. 防幻觉（P0）

|------|------|------|

## 4. 溯源字段（P1）

## 5. 会话与流式（P1）

| 编号 | 步骤 | 预期 |
|------|------|------|
| TC-5.1 | 仅 `/ask` 不带 session | 单轮成功 |
| TC-5.2 | 创建 session + WS 提问 | 收到 `agent_step` → `chunk` → `done` |
| TC-5.3 | 同一 session 追问 | 能结合上文或检索到对应条款 |
| TC-5.4 | 发送 `stop` | 停止生成，不崩溃 |

## 7. 建议最低验收集

按顺序跑通即可认为后端完善：

1. **TC-0.1** 健康检查
2. **TC-0.4** 检索 Top-1
3. **TC-2.1 ~ TC-2.3** 编号 / 描述生成
4. **TC-3.1** 库外问题不凭空生成

可选：TC-5.2 WebSocket 流式。
